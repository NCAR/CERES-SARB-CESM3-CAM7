# Science Verification (plot-based) — CERES-SARB-CAM7

*Created 2026-06-27. Companion to `SPEC.md` and the two implementation plans under
`docs/superpowers/plans/`. This doc defines the **plot-based science-verification gate**
that runs **after each smoke-test run** for SP1 and SP2. It extends TDD past "the code
runs / asserts pass" to "the **physics** is right", using **DAVINCI** to render fields and
**multimodal inspection** (a human or Claude reading the PDF against an explicit checklist)
as the acceptance gate.*

## 0. Principle & cadence

- **Numeric asserts prove the plumbing; plots prove the science.** A green pytest/round-trip
  assert can still hide a wrong dust belt, an inverted sign, a vertical profile that the
  "uniform column rescale" (D4) silently distorted, or a radiation response that never fired.
  Each smoke test therefore emits a small fixed set of PDFs with **explicit acceptance
  criteria**, and inspection of those PDFs is a required step before the task is "done".
- **Cadence:** verification plots are produced **at the end of each smoke-test run**
  (SP2 Tasks 8/10; SP1 Task 18 integration), not as a separate activity. The YAML analyses
  are committed so the gate is repeatable and reviewable.
- **Tooling:** the `davinci` conda environment at
  `/glade/work/fillmore/miniforge3/envs/davinci`. Every plot is generated by
  DAVINCI's `run` command (`python -m davinci_monet.cli.app run
  analyses/davinci/<analysis>.yaml`); project scripts may prepare numeric
  inputs but must not import DAVINCI plotters or render figures directly.

## 1. DAVINCI analysis boundary

The executable plotting boundary is DAVINCI itself. Project-owned analysis definitions live
under `analyses/davinci/`; the project invokes them with DAVINCI's pipeline `run` command. The former SP1,
SP2, and SP3 direct-render helper scripts were removed on 2026-07-13. Numeric verification
scripts may still write NetCDF or summary inputs for an analysis, but they do not create plots.

The SP2 VP7 setup script may still create a short MAM4 sign-off pair with instantaneous
`dst_a1:I` 3-D aerosol output. A renewed profile plot requires a DAVINCI YAML analysis; there
is deliberately no project-local renderer fallback.

**Upstream DAVINCI fix — robust color limits (general capability, add in SP1 Part A).**
`SpatialPlotter` currently color-scales by data **min/max**. AOD (and most geophysical fields)
is heavy-tailed: a few retrieval-artifact cells at AOD≈5 stretch the colorbar to 0–5 and crush
all real structure (0–1) into the dark floor — the field looks empty. Demonstrated 2026-06-27:
a July-2020 MODIS mean rendered illegible under the default scaling, legible with `vmax=1`.

Add a `robust=True` option (default percentiles `2,98`) and/or a per-variable default
(`aod*` → `vmin=0, vmax≈1`) to `SpatialPlotter`/`build_series`:

```python
# davinci_monet/plots/renderers/spatial/field.py — color-limit resolution
if vmin is None and vmax is None and robust:
    finite = np.asarray(data)[np.isfinite(data)]
    if finite.size:
        vmin, vmax = np.percentile(finite, [robust_pct_lo, robust_pct_hi])
```

with a pytest asserting that an array of `[0.1]*100 + [50.0]` yields `vmax < 1` under
`robust=True`. This is general (every DAVINCI user plotting AOD/precip/NOx benefits), so it
belongs **upstream** alongside the VIIRS reader and uncertainty binning, on branch
`sp1-viirs-aerdb`. Until merged, the helpers pass explicit `vmin=0, vmax=…`.

## 2. SP1 verification — obs pipeline (after a pipeline run; SP1 Task 18)

Run the pipeline for a short window (e.g. one week of the July-2008 test period), then:

**VP1 — Global AOD map** (`aod_map` → `SpatialPlotter`, `vmin=0, vmax=1`, robust).
Render the window/day/month mean of `aod_weighted_mean`. **Physical-feature checklist
(inspection gate):**
- Saharan dust maximum (AOD ≳ 0.6) over N. Africa, plume extending W across the tropical Atlantic.
- Biomass-burning plume over equatorial/southern Africa (and S. America / boreal in season).
- Anthropogenic maxima over the Indo-Gangetic Plain and E. China; Arabian dust.
- Remote oceans (S. Pacific/Atlantic, Southern Ocean) near 0.
- **No high-latitude speckle**: isolated saturated cells over snow/ice/sun-glint indicate QC is
  *not* removing bright-surface artifacts (see §5 baseline — the raw archive shows exactly this).
- Coverage and value range plausible (single 3-h window ≈ few-% coverage; values in [0, ~3]).
**Numeric half:** print coverage %, min/median/max, and global mean (expect ≈ 0.1–0.25 monthly).

**VP2 — AERONET co-location** (`aeronet_scatter` → DAVINCI `ScatterPlotter` + `stats.metrics`).
Source = **our DAVINCI-staged AERONET** (`/glade/work/fillmore/Data/CERES-SARB-CAM7/AeroNet`, Level 2.0, staged by `scripts/stage_obs.py`; SP1 Task 16). Scatter product-vs-AERONET (Ångström-interpolated to 550 nm) with the regression line,
and the seasonal MB/ME/RMSE table (Task 17). **Acceptance (typical MODIS/AERONET skill):**
`|MB| ≤ 0.03`, `RMSE ≤ 0.10`, `R ≥ 0.8`, and **bias-corrected VIIRS** RMSE-vs-AERONET **lower
than raw** (the bias step in provenance must show `rmse_after < rmse_before`). Inspection:
points hug the 1:1 line, no fan/curvature suggesting a residual sensor bias.

**VP3 — Uncertainty & count maps** (`unc_count_maps`). `aod_uncertainty` and `aod_count`
side-by-side. **Gate:** uncertainty is **lower where count is high** (inverse-variance merge
working), no fill/uncertainty contradiction (valid AOD ⇒ finite σ and count>0; fill ⇒ all three fill).

**VP4 — QC before/after (optional but recommended).** Map AOD gridded with QC **off** vs **on**.
**Gate:** the high-latitude speckle present in VP1's raw analogue is **gone** with QC on, while
the dust/smoke/pollution structure is preserved.

## 3. SP2 verification — in-CAM nudging (MAM4 only)

The numeric round-trip assert (`check_integration.py`) stays; these plots add the physics gate. MAM5 work is deferred indefinitely, so do not add MAM5 plots or smoke-run gates unless the user explicitly reopens that scope.

**VP5 — OBS / PRE / POST / RATIO maps over the test box** (`pre_post_maps` → `SpatialPlotter`
+ `SpatialBiasPlotter`). From the h0 file: `AODNDG_OBS`, `AODNDG_MODEL_PRE`, `AODNDG_MODEL_POST`,
`AODNDG_RATIO`, `AODNDG_MASK`. **Gate:** POST ≈ OBS where `MASK==1`; POST ≈ PRE where `MASK==0`
(`SpatialBiasPlotter(POST−OBS)` ≈ 0 inside the box, `POST−PRE` ≈ 0 outside) — the *visual*
form of the round-trip assert, which also reveals **edge/partial-cell** errors a global tolerance hides.

**VP6 — Global model AOD, free vs nudged** (`field_map` on `AODVIS`). Run a paired **free**
(`aod_nudge_on=.false.`) and **nudged** case; map `AODVIS` for each and their difference.
**Gate:** the difference is **non-zero only where obs are valid** and moves model AOD **toward**
the obs (sign correct); elsewhere identical. This is the end-to-end "did the nudge do its job" check.

**VP7 — Aerosol vertical profile, free vs nudged (the D4 shape-invariance test).**
D4 claims uniform column rescale of mass+number "preserves speciation, size distribution, and
**vertical shape**." Verify it directly: output an instantaneous 3-D aerosol field (e.g. a species
mmr such as `dst_a1:I`, or per-layer extinction) in both the free and nudged runs; at a nudged
column plot both profiles (DAVINCI `VerticalProfilePlotter`) **and their ratio vs height**.
Use the shortest active paired run (six timesteps here) so the comparison is made before long
free/nudged drift accumulates. **Gate:** the selected nudged/free **ratio is vertically constant**
(within tol) and equals the instantaneous column `AODNDG_RATIO` — i.e. every level scaled by the
same factor, shape unchanged. A time-mean aerosol profile must not be compared against point
diagnostics. The numeric verifier should scan active nudged cells and select a column that passes
the strict spread/error gate, reporting both candidate count and pass count. A ratio that varies with
height would mean the rescale distorted the profile (a D4 violation) — exactly the kind of error
no column-integrated assert can catch. *(This is the `aerosol vertical profile` plot type called
out in the project brief; if `VerticalProfilePlotter` needs a "two-source ratio" overlay, that is
a candidate DAVINCI contribution.)*

**VP8 — RRTMGP direct-effect response (the CERES/SARB payoff).** Map the **clear-sky** SW TOA
flux difference (`FSNTC` nudged − free) against the `AODVIS` difference where nudged.
**Gate:** increased AOD ⇒ **reduced** clear-sky net SW at TOA (more reflection) over the nudged
region, of physically plausible magnitude (a few W m⁻² per 0.1 AOD); ~0 where not nudged. This
confirms the whole point — that the nudged aerosol actually changed the radiation budget RRTMGP
computes — which the round-trip AOD assert alone does **not** establish.

## 4. Acceptance thresholds (summary)

| Plot | Quantitative gate | Visual gate |
|---|---|---|
| VP1 AOD map | mean ≈ 0.1–0.25; values ∈ [0,~3] | dust/BB/pollution belts present; no bright-surface speckle |
| VP2 AERONET | `|MB|≤0.03, RMSE≤0.10, R≥0.8`; bias `rmse_after<rmse_before` | points hug 1:1, no residual-bias fan |
| VP3 unc/count | σ↓ where count↑; fill-consistent | no valid-AOD/σ contradictions |
| VP5 OBS/POST | `|POST−OBS|<tol` in box; `|POST−PRE|≈0` outside | clean box edges, no partial-cell halo |
| VP6 free/nudged | Δ`AODVIS`≠0 only where obs valid, sign toward obs | localized to obs footprint |
| VP7 profile | nudged/free ratio vertically constant = column ratio | flat ratio-vs-height line |
| VP8 direct effect | Δ`FSNTC`<0 where Δ`AOD`>0; ~0 elsewhere | anti-correlated with AOD increase |

## 5. Demonstrated baseline (planning-time proof-of-concept, 2026-06-27)

To de-risk the gate, a July-2020 MODIS monthly-mean AOD was composited from the seed archive and
rendered both with DAVINCI `SpatialPlotter` and a fixed-range reference. Findings carried into
this protocol: (1) the DAVINCI render path **works** for f09 AOD; (2) multimodal inspection
immediately confirmed the correct dust/biomass/pollution structure **and** flagged the
high-latitude QC speckle (→ VP1/VP4 checklist); (3) the default min/max color scaling made the
map illegible (→ §1 robust-color upstream fix). The seed archive (`/glade/work/tvmora`) is used
here **only** as convenient real AOD for this one-off plumbing check — it is **not** a validation
reference (see SPEC: validation is AERONET + golden-file only).
