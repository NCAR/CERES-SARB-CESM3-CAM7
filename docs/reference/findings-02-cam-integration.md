# CAM Integration & Variant Sprawl

> Subsystem: **CAM6 MODIS/VIIRS AOD Nudging Implementation - Prior Attempt Analysis**  ·  source: prior attempt at `/glade/work/tvmora`

## Summary

This is a prior attempt to integrate MODIS/VIIRS aerosol optical depth (AOD) nudging into NCAR CESM2.2.2 (CAM6 with MAM4 modal aerosol scheme). The implementation nudges model-predicted aerosol constituents (27 species across 4 modes) toward satellite-observed AOD values via relaxation forcing: F_nudge = Alpha * (Target - Model) / TimeScale. The system reads AOD observation files organized by year/month/day/second, interpolates them to the model grid, applies horizontal/vertical window functions to control spatial nudging extent, and computes target aerosol concentrations by matching computed visible AOD to observed AOD through ratio-scaling. Integration occurs through physpkg.F90 (physics package) which calls init/timestep routines. The code was heavily modified post-CAM6 baseline to handle aerosol optics calculations (water uptake, refractive index, wet radius) that would normally reside in modal_aer_opt.F90. A separate "forcing" variant emerged for FHIST (fixed-SST) runs alongside the nudging variant. The implementation suffers from severe variant sprawl: 66+ nudging module copies with minimal effective differences (parameter tweaks to AOD ratio thresholds, variable names, print statements), deposited into Force_AODs directory alongside exploratory water-uptake schemes (Kohler theory variants). Configuration multiplied across 5 namelist definition files and 3+ directory hierarchies (Force_AOD, Force_AODs, Force_AODs_backup, forced_modules, aod_weighted_mean, modules_control_test, cam6_3_133_mods, FHIST). Deployment via SourceMods copies into case directories; no modularity or abstraction.

## Technical findings

- MODULE ARCHITECTURE: nudging_AODs.F90 is a monolithic 3.3k-line Fortran module that declares ~40 global allocatable arrays (Target_AOD, Target_Qaer, Model_Qaer, Nobs_AOD, mlp, RH, lnRH, vmr, B_mode, rdry_mode, Brd, rwet_mode, vmr_wet, vmr_water, wet_ref_real_index, wet_ref_im_index, Model_Qaer_Mode, cext, cabs, casm, pext, pabs, pasm, palb, dopaer, tauxar, Computed_AOD, AOD_ratio) and ~30 scalar parameters (Nudge_Model_AOD, Nudge_AOD_ON, Nudge_AOD_Initialized, Nudge_Beg_Year_AOD, etc.). No separation of concerns: physics, I/O, data structures, optics calculations all mixed.
- TIME LOOP INTEGRATION: physpkg_AODs.F90 calls nudging_init_AOD once during phys_init. Per-timestep, calls nudging_timestep_init_AOD early in phys_run2_init (before radiation), then nudging_timestep_tend_AOD in phys_run2 (after aerosol microphysics, check_energy_chng). This hooks into CAM's standard physics callbacks but forces unconditional allocation and file I/O for any model using this physpkg variant.
- PHYSICS BUFFER INTEGRATION: nudging_AODs.F90 imports physics_buffer module (pbuf_get_index, pbuf_get_field) but does not appear to use pbuf for nudging state; instead uses module-scope allocatable arrays indexed by chunk (begchunk:endchunk). Comments suggest dgnumwet calculation was considered but requires pbuf, abandoned. No integration with CAM's standard physics_buffer registry for history output or cross-module data sharing.
- OBSERVATION I/O: nudging_update_analyses_fv (line 1979+) reads binary netCDF files using nf90 library. Hard-coded variable names ('aod_weighted_mean', 'aod_weighted_mean_modis', 'aod_weighted_mean_viirs'). Expects fixed dimensions (lon, lat) and allocates Lon_anal, Lat_anal, Qanal arrays with dynamic sizes (nlon, nlat from file). Scatters to chunks via scatter_field_to_chunk (phys_grid module). No error recovery; endrun on dimension mismatch.
- AEROSOL OPTICS DUPLICATION: nudging_AODs replicates logic from modal_aer_opt.F90 and modal_aero_wateruptake.F90: water_uptake_mam4 (internal copy), aerosol_sw_properties (computes cext, cabs, casm from wet refractive index), qaer_target_mam4 (computes Target_Qaer from AOD_ratio * Model_Qaer, calls relative_humidity, Create_Model_Qaer_Mode). References hard-coded indices: pnmde(4) = [1,2,3,4] for modes, ncoef=5, prefr=7, prefi=10. Calls modal_aero_wateruptake_dr from real CAM library but duplicates RH computation locally.
- WINDOW FUNCTIONS: Horizontal/vertical windowing via nudging_set_profile subroutine using Heaviside step function parameterization. Parameters: Nudge_AOD_Hwin_lat0, Nudge_AOD_Hwin_latWidth, Nudge_AOD_Hwin_latDelta (3 lat), Nudge_AOD_Hwin_lon0, Nudge_AOD_Hwin_lonWidth, Nudge_AOD_Hwin_lonDelta (3 lon), Nudge_AOD_Hwin_Invert (boolean); vertical: Nudge_AOD_Vwin_Lindex, Nudge_AOD_Vwin_Hindex (level bounds), Nudge_AOD_Vwin_Ldelta, Nudge_AOD_Vwin_Hdelta (transition widths), Nudge_AOD_Vwin_Invert. Hardcoded to single window per simulation (comment: 'The module is currently configured for only 1 window function').
- FORCING LOGIC: nudging_timestep_tend_AOD applies F_nudge = Nudge_Qaer_coef[species] * (Target_Qaer - Model_Qaer) / TimeScale per constituent, per chunk. TimeScale selected by Nudge_Timescale_Opt_AOD (0: 1/analysis_interval, 1: 1/time_to_next_analysis). Target values selected by Nudge_AOD_Force_Opt (0: next obs, 1: linear interpolation between adjacent obs). Nudge_Qaer_prof[27] selects profile type (0=off, 1=constant, 2=Heaviside window) per species.
- HARD-CODED GRID/PATHS: Default path Nudge_Path_Qaer = './Data/YOTC_ne30np4_001/', filename template Nudge_File_Template_Qaer = 'Qaer_advected.%y%calday.%h.nc'. AOD variable names hard-coded in file read (e.g., 'aod_weighted_mean_modis'). Grid dimensions (lat, lon) read from file but checked against module-scope Nudge_nlon, Nudge_nlat (set in nudging_init_AOD from first file load). No parametrization for arbitrary grids; dimension mismatch causes error termination.
- VARIANT SPRAWL IN Force_AODs: 66 F90 modules with naming schemes indicating iterative debugging: nudging_AODs.F90 (canonical), nudging_AODs_040326.F90, nudging_AODs_1.F90, nudging_AODs_2.F90 (sequential variants from earlier experiments); nudging_AODs_nt*.F90 (8 variants testing AOD ratio thresholds: 0.01 vs 0.05 threshold, bounds [0.5, 1.5] vs unbounded); nudging_AODs_qaer_modis*.F90 (20+ variants with suffixes: _AODVISdn, _AODVISdn_DF, _AODVISdn_DF_2, _print_all, _tauxar, _modal_aero_kohler, _kohler_rhdeliques); test_nudging_AODs*.F90 (2 variants); wnudging_AODs_qaer_modis.F90 (misspelled prefix). No systematic version control or naming; timestamps range Aug 2023 - Dec 2025. Diffs show parameter changes: threshold 0.01->0.05, file variable 'aod_weighted_mean' -> 'aod_weighted_mean_modis_old', bounds clamping logic added/removed.
- WATER UPTAKE VARIANTS: Kohler subdirectory contains 19 variants (Oct 2025-Dec 2025) of modal_aero_kohler water-uptake implementations, naming like nudging_AODs_qaer_modis_kohler*.F90, nudging_AODs_qaer_modis_kohler_rhdeliques*.F90 (rhdeliques = relative humidity deliquescence), with suffixes _toplev, _print_all, _rh098, _radsurf_rwetmode indicating different RH computations or diagnostic levels. Suggests active experimentation with water uptake closure (modeled Kohler equilibrium vs CAM default). File sizes range 3.6K-3.8K lines; diffs likely minor RH computation changes.
- FORCING VARIANT (Force_AODs/forcing_AODs_*.F90): Two variants for MODIS vs VIIRS datasets (identical except netCDF variable name: 'aod_weighted_mean_modis' vs 'aod_weighted_mean_viirs'). Module name still 'nudging_AODs', public interfaces unchanged. Deployed as alternative in case directories.
- FHIST COMPSET BRANCH: 8 modules in FHIST/ for fixed-SST runs. nudging_FHIST_soa*.F90 (4 variants for SOA nudging: base, _forced, _nudged, _noforced_nonudged). nudging-FHIST-AODs-forced*.f90 (4 variants, 165K-171K lines each, date range Dec 2023-Jan 2024). All replicate full nudging logic despite common core; no shared base.
- DEPLOYMENT VIA SourceMods: Cases copy entire modules into SourceMods/src.cam/. Example case test_geosit_viirs_nds_2025_06_07 contains: nudging_AODs.F90 (162K on disk, likely with debug output), physpkg.F90 (116K), modal_aer_opt.F90 (77K), aer_rad_props.F90 (41K). Build system (CMake) then compiles SourceMods in-place; no version pinning, no history, no merge conflict detection. Each case freezes a snapshot.
- NAMELIST PROLIFERATION: 5 distinct namelist_definition*.xml files (320K-365K lines each): namelist_definition.xml (orig CAM), namelist_definition.xml (Nov 2023, cam6_3_133_mods), namelist_definition_nudge_FV.xml, namelist_definition_nudge_FV_2.xml (attempted fixes?), namelist_definition_nudging_AOD.xml (singular), namelist_definition_nudging_AODs.xml (plural, 328K lines). Last one defines nudging_AOD_nl namelist block with ~50 parameters (Nudge_Model_AOD, Nudge_Path_Qaer, 27 Nudge_Qaer_coef values, 27 Nudge_Qaer_prof values, window params, time bounds). No merging; users reference specific versions in cases.
- CONSTITUENT INDEXING: Hard-coded 27-species MOD4 indices allocated at lines 416-419 (so4_a1, pom_a1, soa1-5_a1, bc_a1, dst_a1, ncl_a1, num_a1, so4_a2, dst_a2, soa1-5_a2, ncl_a2, num_a2, dst_a3, ncl_a3, so4_a3, num_a3, pom_a4, bc_a4, num_a4; then idxaer[27] array). Queries via cnst_get_ind(cnst_name, idxaer); no abstraction for alternate aerosol schemes. Arrays Target_Qaer, Model_Qaer, Nobs_Qaer, Nudge_Qaer_tau, Nudge_Qaer_step all dimensioned pcnst (=27) forcing tight coupling to MAM4.
- CODE QUALITY ISSUES: (1) Global state: 40+ module-scope arrays and 30+ parameters visible across all subroutines, no encapsulation. (2) Copy-paste replication: 66 nudging_AODs variants differ by <50 lines per diff (parameter tweaks, print statements, variable name changes). (3) Dead code: Commented blocks (e.g., calc_MidpointPressure at lines 2413+, nudging_update_analyses_se/eul at lines 1213-1215). (4) Magic numbers: pnmde(4), ncoef=5, prefr=7, prefi=10 (indices into opacity coefficient arrays) not documented. (5) Error handling: No graceful fallback; netCDF read failures call endrun (abort). (6) I/O overhead: nudging_update_analyses_fv reads entire netCDF file each call (per analysis time step); no caching. (7) Naming: Nudge vs nudging (inconsistent); AOD vs Qaer (mixing observation vs state variables); nt, DF, SK suffixes (test tags left in repo).
- CIRCULAR DEPENDENCIES AND REDUNDANT CALCULATIONS: qaer_target_mam4 computes AOD_ratio via (a) call water_uptake_mam4 to get wet properties, (b) call aerosol_sw_properties to compute extinction, (c) divide observed AOD by computed AOD to get scaling ratio. This mirrors logic in modal_aer_opt.F90 + modal_aero_wateruptake.F90 but without ability to reuse CAM's internal state; forces re-computation per nudging timestep. relative_humidity implemented locally (lines 2639+) with RH = pmid * q / (eps * e_s_0 * exp(...)) formula; ignores CAM's moisture diagnostics.
- TIME MANAGEMENT: Time of nudging observations loaded lazily on first call to nudging_timestep_tend_AOD; two analysis times stored (Nudge_AOD_Curr/Next, Nudge_AOD_Curr/Next_Year/Month/Day/Sec; corresponding Model_AOD_Curr/Next). Linear interpolation weights computed as F = (t_next - t_current) / Delta_analysis. No handling of observation gaps or data assimilation windows >1 analysis period. nudge_beg/end times hardcoded per namelist (year/month/day); no flexibility for time-varying forcing protocols.
- PLATFORM-SPECIFIC BUILD: CmakeList_AODs.txt (Force_AODs) appends nudging_AODs.F90 to cam_sources list. physpkg_AODs.F90 conditionally included in main physpkg module (line 38 commented out 'use nudging_AODs', line 765 uncommented). No #ifdef guards, no optional compilation. Case setup copies entire module; build always succeeds but contains dead code if nudging disabled.
- HISTORY OUTPUT INTEGRATION: nudging_AODs registers fields Nudge_Qaer (tendency) and Target_Qaer (target) for history file output via addfld/outfld (cam_history module). No pbuf registration. Output variables written per constituent (27 species), creating large history files.
- TESTING AND VALIDATION: modules_control_test directory contains 52 variants labeled control_test_nudging_update_analyses_*.f90 (versions 1-9e, 4a-4g variants). Suggests iterative debugging of nudging_update_analyses_fv (file I/O and target calculation). No automated tests; variants appear to be snapshots saved during interactive troubleshooting. No regression tests, no CI pipeline visible.


## Problems / why it's a mess

- VARIANT EXPLOSION: 66 nudging module copies + 5 namelist definitions + 3 directory silos (Force_AOD, Force_AODs, Force_AODs_backup; aod_weighted_mean, modules_control_test; cam6_3_133_mods; FHIST) = >100 versions of same logic scattered across filesystem. Timestamps show ongoing iteration (Aug 2023 to Dec 2025) with no version control or archival strategy. Users cannot identify which variant is 'correct' or 'latest'. Maintenance nightmare: bug fixes must be applied to 66+ files independently.
- NO MODULARITY: nudging_AODs.F90 is 3.3K-line monolith mixing I/O, numerics, data structures, optics, windowing. Any reuse (e.g., testing windowing function alone) requires copying entire 3.3K lines. No separate modules for: file I/O handler, window function library, constituent indexing, optics subroutines, nudging kernel.
- GLOBAL STATE AND MEMORY LEAKS: 40+ allocatable module-scope arrays (Target_AOD, Target_Qaer, Model_Qaer, Nobs_AOD, etc.) allocated in nudging_init_AOD but never deallocated. Allocated with fixed shapes (pcols, pver, pcnst, begchunk:endchunk) => NLEV/NCOL/NMODE dependent; no way to resize for different grids. Module 'save' attribute (line 42) prevents re-initialization.
- CIRCULAR LOGIC AND REDUNDANT COMPUTATION: (1) nudging_init_AOD loads one observation file to infer grid dimensions (nlon, nlat), stores in module-scope Nudge_nlon, Nudge_nlat; then allocates all arrays. Subsequent files must match exact grid or run fails. (2) qaer_target_mam4 calls water_uptake_mam4 + aerosol_sw_properties to recompute aerosol optics every nudging step, even though CAM has already computed optics for radiation. Creates divergence between nudging-computed and radiation-computed AOD. (3) relative_humidity computed locally (RH = pmid*q/(eps*e_s0*exp(...))) instead of using CAM's existing saturation vapor pressure functions.
- HARD-CODED PATHS AND GRIDS: Default Nudge_Path_Qaer = './Data/YOTC_ne30np4_001/' suggests tied to ne30np4 FV3 grid. AOD file variable names hard-coded ('aod_weighted_mean', 'aod_weighted_mean_modis', 'aod_weighted_mean_viirs'); if user provides file with different variable naming, code fails silently on nf90_inq_varid, then endrun. Grid mismatch (nlon, nlat) detected but causes fatal error, no interpolation fallback.
- DEPLOYMENT FRAGILITY: SourceMods deployment copies entire module into case directory; no dependency tracking, no build artifact caching. If user modifies namelist but forgets to re-copy nudging_AODs.F90, mismatch between namelist parameters and code logic goes undetected. 94 case scripts in CAM_scripts/Derecho_CESM_scripts with hardcoded paths to CAM_modifications subdirs (e.g., 'Force_AODs' vs 'Force_AODs_backup'); cases become stale if directory renamed.
- UNCONTROLLED ITERATION: modules_control_test/ contains 52 'control test' variants (control_test_nudging_update_analyses_*.f90) from Feb 2024, apparently abandoned. Kohler/ directory has 19 variants (Oct-Dec 2025) with active modification timestamps but no documentation of experiment goals. No commit messages, no README files, no issue tracking visible.
- TESTING GAPS: No unit tests for window functions, nudging kernel, or file I/O. No regression tests comparing against known-good output. modules_control_test/ appears to be ad-hoc debugging snapshots (version 1-9e, 4a-4g suffixes), not systematic test suite.
- TIME MANAGEMENT RIGIDITY: nudging beg/end dates hard-coded in namelist (year/month/day). No support for: (a) multi-year climatological nudging, (b) nudging with observation gaps, (c) spin-up periods where nudging is disabled then enabled mid-run. Model times per day and analysis times per day must be configured manually; no automatic inference from file metadata.
- PHYSICS BUFFER MISMATCH: physpkg_AODs.F90 imports physics_buffer module but nudging_AODs does not register arrays with physics_buffer; instead uses module-scope allocatable arrays. This means nudging diagnostics cannot integrate with CAM's standard pbuf history mechanism. Comments suggest pbuf integration was attempted (dgnumwet) but abandoned ('dgnumwet needs pbuf').
- CONSTITUENT COUPLING: All arrays dimensioned pcnst (hardcoded=27 for MAM4). Adding a new aerosol species requires modifying Nudge_Qaer_coef[27], Nudge_Qaer_prof[27] arrays and recompiling. No abstraction layer; strong coupling to MAM4 modal aerosol scheme. Cannot use same code with CAM3 bulk aerosol or other modal schemes.
- BOUNDARY CONDITION CONFUSION: Three separate systems visible: (1) original nudging.F90 / nudging-forced.F90 for T,U,V,Q nudging (still in root), (2) nudging_AODs.F90 for AOD nudging (new), (3) forcing_AODs_qaer_modis/viirs.F90 (variant that seems to 'force' rather than 'nudge'?). No documentation of difference between 'nudging' vs 'forcing' terminology; users unclear on which compset to use.
- AEROSOL SCHEME LOCK-IN: Code tightly coupled to MAM4 (4 modes, 27 species). References hard-coded mode indices pnmde(4)=[1,2,3,4] and species counts. CAM6 supports prescribed aerosol, CAM3 aerosol, and other schemes; code incompatible with any alternative.
- FILE I/O ROBUSTNESS: netCDF open/read/close in single-threaded path (if (masterproc) then ... endif), then scatter to chunks. No error recovery if scatter fails. File paths resolved at runtime; typos discovered only after model hangs waiting for file. No logging of which file was loaded, when, what time stamps.
- DEBUGGING ARTIFACT: Numerous debug/test print statements in active code (e.g., print*,'Aerosol file ',trim(aer_file) at line 2048). Case runs produce verbose log output, hard to distinguish signal from noise.

## Carry forward vs discard

- REUSABLE PATTERNS: (1) Window function parameterization (Heaviside step with dual horizontal/vertical control) is elegant and worth preserving. (2) Chunk-based scatter_field_to_chunk for distributed memory is standard CAM pattern; reuse as-is. (3) Namelist-driven configuration (nudging_AOD_nl block) is correct approach; consolidate duplicates to single definition.
- KEEP FROM CURRENT CODE: (1) Core nudging formula F_nudge = alpha * (Target - Model) / TimeScale is proven; (2) target selection logic (next-obs vs linear interpolation) has two proven options; (3) netCDF file reading and variable name mapping (extend with configurable variable names, not hard-coded); (4) constituent indexing via cnst_get_ind (reuse CAM's infrastructure, don't replicate); (5) modal_aer_opt optics calculations (reuse existing CAM modules, don't duplicate in nudging); (6) time management for observations (cached Curr/Next pairs, linear interpolation weights) is sound.
- DISCARD: (1) All 65 variant nudging_AODs copies — keep only canonical version. (2) Hand-rolled water uptake, RH computation, extinction coefficient calculation — reuse CAM's modal_aero_wateruptake and modal_aer_opt. (3) modules_control_test/ and Kohler/ exploratory variants — archive to separate 'research' branch or remove. (4) forcing_AODs_* variants — if truly needed, parameterize via namelist flag, not separate module. (5) Dead code (commented-out functions, calc_MidpointPressure, nudging_update_analyses_se/eul). (6) Debug print statements in production code paths.
- ARCHITECTURAL IMPROVEMENTS: (1) Split nudging_AODs.F90 into: (a) nudging_kernel.F90 (core F_nudge formula, window functions, time interpolation), (b) nudging_io.F90 (netCDF file reading, grid validation, constituent mapping), (c) nudging_aer_optics.F90 (wrap CAM's existing modal_aer_opt and modal_aero_wateruptake, compute AOD target from constituents), (d) nudging_phys_interface.F90 (hooks into physpkg, memory management). (2) Use CAM's physics_buffer for all nudging state (nudge tendencies, targets, diagnostics); register in phys_register, use pbuf_get/put in time loop. (3) Create standalone unit tests for window functions and nudging kernel (no need for full CAM build). (4) Single namelist definition file; use CAM's namelist infrastructure for validation. (5) Parameterize AOD variable names ('aod_weighted_mean_modis' vs 'aod_weighted_mean_viirs') as namelist option, not hard-coded.
